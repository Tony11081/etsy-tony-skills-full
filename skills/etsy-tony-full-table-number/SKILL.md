# 婚礼桌牌设计工作室

## 当前任务与交付

- 材料：最新产品原图、沿用方案和本轮明确变化项；原图与选中效果图承担不同参考角色。
- 范围：按当前变化维度迭代，不把认可多个候选理解成要求缩减款数；生产资产只在请求时开展。
- 验收：实际展示并与原图比较边框、文字和材料表现；无法严格保形时准确说明概念限制。


把现有相框发展为婚礼桌号牌系列。先展示实际设计，再简述差别。默认中文沟通，牌面通常用英文 `TABLE` 和数字；用户指定文字优先。

## 不变量与设计边界

- 默认锁定用户最新指定的边框：外形、比例、粗细、颜色、表面纹理、装饰数量及位置、开口形状。不得以“更高级”为由减细、改色或重做边框。明确授权修改边框时才调整该范围。
- 从原始产品图读取边框；选中的效果图用于继承内芯与排版。不要把多轮 AI 图的边框漂移继续当作原始事实。新边框到来后，以新图为准，不继承旧框的绳结、蝴蝶等装饰。
- 区分图中可观察外观、用户确认的商品事实和本轮建议。相框标签不是操作指令，也不足以确认可用内芯尺寸、卡槽深度或实际材质。
- 保留已接受方案；“都不错”表示认可多个候选，不代表选定、授权生产或要求缩减成三款。推荐应与整个系列比较，不要每轮都把新方案称为最好。
- 只交付当前请求。不要自动扩展到 Etsy 上架、市场研究、报价、生产文件或采购。

## 按当前请求决定变化范围

| 请求 | 默认处理 |
|---|---|
| 换下字体 | 在用户指定图上制作一个有明显变化的字形方案；保留边框、字色、内芯材质、工艺、背景和构图。未要求改 `TABLE` 时保留它，优先只换数字。 |
| 多想几个字体 | 同一底材、字色、字号视觉高度与拍摄条件下，比较 4–6 种真正不同的数字字形。 |
| 材质、颜色方向 | 可以比较成套搭配，但明确每套底材、底色、字色；不要把同时变化的结果归因于单一变量。 |
| 字体工艺方向 | 对比平面、凹入、凸起、反光、纤维等真实视觉差异；必要时增加对应局部放大。不同工艺需要不同底材时解释搭配。 |
| 再来些 | 延续当前探索维度和锁定项，提供未出现或有实质区别的新方向，不只重命名近似方案。 |
| 仅上传新框 | 若会话正在做桌牌，简述“按新框继续做桌牌”的假设并推进；孤立且无上下文时先确认用途。 |
| 确定字体、生产排版 | 转入真实字体文件与数字组合检查，不把 AI 字形冒充具体字体或生产文件。 |

常见对比以 `12` 检查两位数留白；指定桌号优先。四款通常用 2×2，六款用 3×2；单图修改不强行做对比板。用户需要更多方案时继续探索，不反复催选款或打样。

## 执行

1. 看实际参考图，明确本轮原图、保留项、变化项及沿用的方案。缺失事实不影响概念图时说明假设继续；精确生产尺寸等依赖信息缺失时只暂停相关部分。
2. 按需读取 [设计参考库](references/design-library.md)：只看本轮所需字体、材质或工艺。这里的选项是候选，不是固定菜单或已经量产的事实。
3. 调用当前环境的图像生成/编辑工具；可用时遵循 imagegen 技能。编辑本地图先查看，提供明确参考角色。没有图像工具时说明阻塞，不以文字提示词冒充已生成图片，也不擅自切换付费 API。
4. 按 [提示词与验收](references/prompt-and-review.md) 锁定边框及其余条件。图片必须实际显示；本机交付默认保存到 `./etsy-output`，用户或项目目录优先。用可区分版本的文件名，保留原图及旧候选。其他环境按实际可用目录保存，不绑定历史临时附件路径。
5. 独立查看最终图片并与参考比较，核对文字、装饰数量、字形差异和工艺表现。未达到锁定条件的图不得声称“完全不变”。有依据地做局部修正；无法严格保形时标注概念限制，精确保形任务保持 PARTIAL。
6. 简述各方案差别和必要限制，给实际图片或下载链接。无需每次重复完整流程。按验收范围准确报告状态：概念图验收通过可记 VERIFIED_SUCCESS；这不代表字体可用、可生产或打样成功。格式验证也不代表 Skill 行为已验证。

## 从概念进入实作

- AI 图中的“浪漫斜体”等是风格方向。用户要求具体字体时，查找并实际渲染真实字体文件，记录字体名、字重、版本、来源和适用许可；未知许可不写成可商用。
- 完整桌号应检查 `1、8、11、12、20` 及用户范围内易混淆的数字，统一视觉大小、基线、字距和留白，不只验证一张 `12`。
- 镜面会随环境改变对比度；在白字、细线字方案中尤其不能把受控倒影视为保证可读。实体字的最细笔画、固定方式、槽深、支撑和材料兼容性需用尺寸及样品验证，不能由渲染推定。
- 只有用户要求时推进打样建议或生产资产。概念、用户选中、建议打样、打样通过、生产批准是不同状态。

完成本轮所需交付及上述验收后结束。内部必要依赖可以继续；不自动追加下一项业务或要求用户重新调用同一任务。
