# 家具尺度产品：比例与"有人住过"规则

**仅当产品是家具或家具尺度物件时读取。** 小型可穿戴、手持工具、桌面物件不因尺寸小而适用本文件。本文件把家具专属规则从通用路径中独立出来；它源于紧凑家具（床头柜、边桌、凳子、小柜）与人手同框时"产品像玩具"的失败模式。

## 1. 计划字段 `furniture_scale`

家具产品在计划里加 `furniture_scale` 对象：

| 字段 | 内容 |
| --- | --- |
| `function_class` | 座椅 / 餐桌·工作桌·茶几 / 收纳 / 床头·玄关 / 层架·陈列 / 其他有证据的类别 |
| `supported_interactions` | 参考图和产品身份支持的动作：坐、取、工作、用餐、放下、拿起、开、关、陈列、经过… |
| `unsupported_mechanisms` | 参考图未验证、不得展示的抽屉、门、延伸、铰链、层板、承重、隐藏功能 |
| `compact_policy` | 见第 2 节：`locked_dimensions` / `conservative_visual_classification` / `not_applicable` |
| `lived_in_floor` | 见第 3 节：该档需要的"有人住过"图数与计划的镜头编号 |

## 2. 紧凑家具比例策略（`compact_policy`）

**触发条件**：确认宽度 ≤ 20 in / 50.8 cm，或确认高度 ≤ 25 in / 63.5 cm → `locked_dimensions`。无尺寸但已验证类别明显是床头柜、边桌、凳子或类似紧凑柜 → `conservative_visual_classification`。其他 → `not_applicable`。

触发后：

- `human_presence_budget` 默认为 **0**。仅当某个具体互动回答决策关键的买家问题、且用户明确要求或批准时，允许最多一张含人图。
- 主图、尺寸图、房间适配/动线证明、收尾图中不出现可见人体。
- 比例锚优先用锁定尺寸 + 稳定的房间/家具锚：床或床垫边缘、椅子、门框、踢脚线、地板条、已核实的房间间距。**不用手、手机、小书作为主要比例参照**——它们物理上合理，却仍会造成迷你印象。
- 若使用被批准的例外：只露指尖，无手掌、手腕、前臂、全身或前景肢体；指尖与产品在同一中景平面；产品视觉主导；偏好 70–85 mm 等效的中长焦视角；可见手掌跨度接近产品宽度 25% 是规划警告，不替代目视判断。该图必须作为探针先于所有其他含人图生成。
- 探针命中任一拒绝项（第一眼像迷你/玩具、手或肢体压过产品、人比产品更靠近相机、身体/产品透视不一致、用户表示比例不适）→ `human_probe_result: reject`，预算归零，所有计划含人镜头改为隐含使用者或无人路线。**不为满足模板再试另一条人物路线。** 用户的比例否决覆盖内部通过。

默认集可以零人物并仍满足必带 prompt 的"人物使用效果"意图：已验证的抽屉/门状态变化、具体的使用前/后日常、无可见身体的物品收放、其他隐含使用者证据。

## 3. "有人住过"下限（`lived_in_floor`）

普通住宅家具：房间适配、舒适、日常仪式、陈列或拥有是主要购买驱动时选 `experience_led`；构造、状态、收藏价值、部件证明、安装或兼容性真正主导时选 `balanced`——不因产品大就选 balanced。

- `experience_led` 家具：至少 **4** 张实际通过 lived-in 的图，含至少一张功能证明或已验证的产品状态变化、一张进行中的日常/过渡、一张比例/动线关系；至少一张在前五张。
- `balanced` 家具：能真实展示住宅使用时至少 **3** 张，含至少一张功能证明、已验证状态变化或进行中日常。
- 按渲染结果计数，不按计划标签。只有装饰房间里未被触碰的产品 → 重新分类为无 lived-in 证据的情境证据；未达下限时替换。

lived-in 下限**从不要求可见人物**。触发紧凑策略的产品完全通过受支持的状态变化与具体使用者痕迹达标。

## 4. 每张家具场景的 `lived_in` 块（写入 shot 与 prompt）

- `daily_moment`：使用前、中、后正在发生什么；
- `interaction_or_owner_trace`：直接身体/手使用、进行中的任务、可信的过渡，或具体的隐含使用者痕迹；
- `physical_response`：画面中可见的接触、重量、压力、伸手、位移、间距、移动路径或物品关系；
- `product_dependency`：为什么没有这件家具这一刻会不完整或明显不同；
- `unsupported_action_to_avoid`：参考图未验证的开合、装载、延伸、机构、容量或姿态。

按已验证的家具功能选时刻：座椅 → 可信的坐、伸手、阅读、交谈、起身过渡，或刚被占用的状态，身体比例、接触、重量、坐垫/面料响应正确；餐桌/茶几/工作桌 → 具体活动进行中（工作、上菜、聚集、整理、放下），手/物按使用关系摆放而非造型对称；收纳 → 仅当参考图可见相关门、抽屉、层板、开口时展示收放，否则展示真实的闭合放置与动线；床头柜/玄关 → 可信的到家、出门、睡前、早晨或日常随身物过渡；层架/陈列 → 以可信的伸手距离与间距选取、放置或观看物品，而非对称道具墙；大件/特殊件 → 强调接近、间距、身体比例、移动路径、安装关系或受支持的使用。

**通过标准**：清楚的时刻 + 可观察证据（身体接触、手部动作、重量、已验证的抽屉/门位移、使用中的物品、拉出的座位、可及的间距、前/后过渡）。花、书、杯子、毯子、植物、地毯、灯，或一个站着看镜头的人，本身不构成 lived-in 证据。一个人站在家具旁、面向相机、把家具当摆姿道具，也不通过。

不通过杂乱、假磨损、未验证的儿童/宠物、夸张凌乱、全脸模特或黄/橙调色来制造生活感。lived-in 改变的是动作与空间关系，不是产品真实或中性白平衡基线。家具必须主导且结构精确：不虚构抽屉、不打开未见过的门、不改层板数、不加坐垫、不假做旧、不暗示无支撑的承重、不遮挡买家关键构造。

## 5. 最终审计中的家具项

- 每张家具场景记录 `lived_in_evidence`：互动/使用者痕迹类型、可见物理响应、是否达到家具专属标准。
- 分别计数实际通过 lived-in 的最终图，对照 `lived_in_floor`。
- 多张房间场景都显示未触碰的家具、无使用关系或过渡、只有装饰道具 → 判定"空展厅簇"，即便它们通过了更宽泛的场景承载测试，也要重生成弱图并重建样片墙。
- 紧凑家具留在声明的 `human_presence_budget` 内；被用户否决的人物比例路线不能留在 `VERIFIED_SUCCESS` 集合里，即便早期内部审计通过过。
- `experience_led` 家具至少一张 lived-in 图在前五张。
