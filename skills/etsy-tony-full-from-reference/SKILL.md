# Etsy New Product From Reference

## 当前任务与交付

- 材料：自有产品的可读照片、参考图、已确认的尺寸与材质。
- 范围：单产品一轮；默认交付改款图 / 15 张商品图 / Listing 文案中用户明确要的那些。
- 验收：产品身份不被改动；参考只贡献设计语言；每张图可逐条核对；未确认事实不进图、不进文案。

## 何时使用

- 用户给一张参考图和一张自己的产品图，要求"换成这个""参考这个重新设计""学习这个字体/工艺"。
- 用户要把已定稿的产品做成整套 Etsy 商品图和文案。

不适用：
- 从竞品开发一个**结构不同的新品** → `../etsy-tony-full-original-product/SKILL.md`。
- 只要 15 张图、产品已定稿且无参考迁移 → 直接 `../etsy-tony-full-photo-15/SKILL.md`。
- 只做可行性分析 → `../etsy-tony-full-product-studio/SKILL.md`。

不要在同一次交付里同时跑两个开发主控。用户已经选定的路线和上游确认过的事实，后续步骤必须继续沿用。

## 四条不可动的原则

1. **参考只学语言，不抄设计。** 参考图只能提供买家需求、品类通用语言、字体气质、颜色区间、层级关系、工艺观感。不得复制：具体字母组合、装饰线布局、独特纹样、整体视觉印象、轮廓、logo、水印、标题文案。改颜色或改文字不构成原创。
2. **每轮只改一个变量。** 执行前先把不变量点名写出来（文字内容、场景、构图、光线、产品几何）。一轮只动用户指定的那一样。改动后逐项核对不变量有没有漂移，漂移了就重做，不接受"画面更好看但产品被改了"的结果。
3. **批量前先出探针。** 不得一次性生成整套。先出 1 张验产品保真（轮廓、部件数量、纹样、镜面/表面质感）；计划含人物的，再单独出 1 张验人体尺度。探针不过就修正探针，不进入批量。
4. **事实门。** 未经用户确认的事实一律保持 Unknown：材质、工艺、尺寸、包装、背板结构、内含物、可选项范围、价格、发货。Unknown 不进图、不进文案、不进标签。宁可少写。

## 产品身份档案（每个产品一份，先读后写）

这是本 Skill 与单次会话的区别：用户教过一次的标准必须落盘，下次不用重教。

开工第一步：在输出目录找 `product-identity.json`。存在就读取并沿用；不存在就在本轮结束前写出来。

以下是虚构的结构示例。填写时以当前商品证据为准。

```json
{
  "product": "椭圆形展示托盘",
  "confirmed": {
    "dimensions": "示例尺寸 10 × 15 cm",
    "surface": "浅色哑光外沿、镜面内芯"
  },
  "unknowns": [
    "外框材质",
    "内芯材质",
    "背板结构",
    "包装"
  ],
  "visual_standard": {
    "font_primary": "纤细连写体",
    "color": "低饱和暖金",
    "placement": "内芯中下部，避开边缘"
  },
  "craft_unverified": "参考图只能确认视觉效果，实际文字工艺待卖家确认",
  "approved_references": [
    "approved-visual-reference.png"
  ]
}
```

用户说"学习这个""工艺 颜色都要学习"时，把提取到的标准写进 `visual_standard` 并回读确认；用户说"用之前学的字体"时，直接读这份档案执行，不再追问。

`craft_unverified` 不得删除：效果图永远不能证明实物工艺。

## 路线 A：改款

用户给参考款 + 自己的产品图，要求替换某个部件。

1. 点名不变量，写给用户看。
2. 只替换指定部件，按参考核对该部件的关键特征（例如冠饰、侧边雕花、底框、收腰曲线）。
3. 生成后逐项回看不变量；文字类不变量要能在图里读出来。
4. **每一款存独立文件名，不覆盖前一版**，便于横向对比。
5. 标注状态：`VERIFIED_SUCCESS（概念图）`，并说明生成式编辑不保证背景逐像素一致。

用户连续给多张参考要求"换成这个"时，每张都从**最初的底图**重做，不要在上一版结果上叠加，否则误差累积。

## 路线 B：学设计语言并迁移

1. 先只做拆解，不出图。把参考拆成：主字体特征、连接符号、装饰结构、副文字、颜色、层级、整体气质。明确列出**可借鉴**与**必须避开**两组。
2. 说明迁移到自有产品时要怎么改：按自有产品的轮廓重新设计装饰线、按表面情况选放置区域。
3. 用户说"生成图片"后再出图。示例文案在用户未提供真实内容时自行设定并标明是示例。
4. 单点迭代：用户说"换一个字体""金色的字体""这个图案刻上去"，每次只动那一项。若新版与上一版差异不明显，不要交付，直接再做一次更明确的修改。
5. 文字准确性是硬门槛：字母、连接符、日期标点必须逐字核对。`May,24,2026` 这类标点错误一律重做。

## 出 15 张商品图

加载 `../etsy-tony-full-photo-15/SKILL.md` 并完整遵守，本 Skill 额外要求：

- 开工前把产品身份档案里的 `confirmed` 和 `unknowns` 填进它的产品事实门，不要重新问用户。
- 尺寸、单位、线条一律在生图后用确定性方法（SVG / Pillow / HTML-CSS）叠加，不让生图模型写数字。同时保留无字原图 `shot-NN-clean.png`。
- 用户中途补充产品事实（例如"我们的是镜面银色亚克力，要有反光"）时，**已生成但不符合新事实的图全部作废重做**，不保留。
- 整套没做完不得标 `VERIFIED_SUCCESS`；缺号保留空缺，在报告里写明缺哪几张和原因。

## Listing 文案

加载 `../etsy-tony-full-listing/SKILL.md`。只使用产品身份档案里 `confirmed` 的事实，`unknowns` 不写进买家文案。

用户给出一个标题格式样例时，照格式重排，不改变已确认事实。

## 输出

同一产品的全部产出落在同一目录：

```text
etsy-output/<product-slug>-<yyyymmdd>/
  product-identity.json
  variants/                  # 路线 A 的各版改款图，一版一文件
  shots/                     # 15 张商品图 + shot-NN-clean.png
  rejected/                  # 有意义的保真失败
  listing.md                 # 标题 / 标签 / 描述
  plan.codex-direct.json
  fidelity-audit.json
```
