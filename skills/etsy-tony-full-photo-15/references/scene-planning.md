# 场景规划、生活场景方向与色温

当 `scene_capacity` 为 `experience_led` 或 `balanced`、且整套包含生成的生活/使用/送礼/拥有场景时读取第 1、2、4 节。`proof_led` 且无真实情境的产品跳过这三节，只需在计划里写明"场景下限不适用"的原因。**第 3 节（色彩准确、氛围与白平衡门）对所有产品、所有镜头模式（含纯棚拍与确定性图）都生效，任何 campaign 不得跳过。** 场景从计划里的 `art_direction` 取（photo-engine 的 art-direction.md 与 scene-library.md）：本文件管场景数量、承载标准和色彩门，视觉世界、光、色板、道具卡司由 `art_direction` 定。 本文件不替代产品事实、尺寸、变体、授权与发布就绪规则。

## 1. 五种镜头模式与场景下限

先完成视角分配，再规划环境。**换环境不得把产品悄悄重置回每张都一样的正面姿态。**

每张图归入一种模式：

- `studio_evidence`：无缝、纯色、渐变、纸/布、展台或孤立微距，目的是干净的事实证据；
- `contextual_evidence`：嵌入可辨认的类目原生地点或空间关系中的事实证据；
- `functional_use`：产品被真实地穿戴、拿取、安装、操作、装填、打开、选择或使用；
- `ownership_story`：可信的拥有前/中/后时刻，制造产品特定的欲望或意义；
- `deterministic_graphic`：比较、选项、说明或尺寸构图，精确文字与线条在生成后叠加。

| 场景容量 | 场景承载目标 | 下限 | 方向 |
| --- | ---: | ---: | --- |
| `experience_led` | 9–11 | 8 | 结合欲望、真实使用、比例、材质、送礼或拥有，不重复同一环境 |
| `balanced` | 6–8 | 5 | 环境证据与干净的部件/状态/兼容/内容证据平衡 |
| `proof_led` | 3–5 | 有真实情境时 3 | 偏向真实安装、工作台、兼容或工作流情境；不编造情绪化生活场景 |

**场景承载标准**（按实际渲染判定，不按 prompt 标签）：至少两项可见且可信——可辨认的真实地点或空间锚（房间结构、家具关系、工作台、身体、电器、墙、架、风景、活动场地）；产品与环境的接触或使用（悬挂、有重量地放置、被穿戴、安装、装填、打开、握持、选择、打包、操作，或以有意义的比例陈列）；前/中/后景深度或其他清楚的空间层次；没有产品就不完整的买家时刻、动作、过渡或使用者存在。**纯色、无缝背景、纸/布纹理、孤立展台、渐变、叶影、绿植角、光斑本身不构成场景**，归 `studio_evidence`。

**氛围下限另算。** 上表数的是「有没有场景」，photo-engine 的 atmosphere.md 第 3 节数的是「场景够不够」：每张图标 `scene_level`，一面墙加一两件小道具是 `L1`，不计入场景承载；`occasion_led` 产品 15 张里主图 `L3`、至少 5 张 `L3`、`L2` 加 `L3` 至少 9 张，`lifestyle_led` 主图 `L2` 以上、至少 3 张 `L3`、合计至少 7 张。两套下限都要过。

序列门：

- `experience_led`：前五张至少两张场景承载；整个轮播任何位置不连续出现超过两张纯色/棚拍/信息板图。
- `balanced`：前五张至少一张场景承载；在事实棚拍图之间穿插情境证据有助理解。
- 兼顾型证据图：在准确性清楚的前提下，用真实空间关系证尺寸、在情境中证材质、在选择/陈列/使用中证个性化、在工作台或序列中证内含物、在受控的类目原生情境中证变体。但不把每张证据图都变成生活照：精确色彩比较、脆弱细节、状态、兼容性、确定性文字可能需要隔离，记录这些例外并把场景预算花在别处。
- 计划里 `scene_counts` 写实际计划数 / 下限与预算。审计按最终图重新计数：计划的房间/使用/拥有场景若渲染成彩色底上的孤立产品，按 `studio_evidence` 计并替换或重新平衡。

每张场景承载镜头的 `scene_anchor` 写：具体地点与买家时刻；时间或有动机的光源；前中后景元素；物理承载产品的表面/墙/身体/固定物；产品接触、重量、反射、阴影、位移、张力或运动；声称使用或拥有时的可见动作或使用者证据；这个环境与其他每个场景的不同点。避免"漂亮房间的桌上放着产品"——写能被拍到的空间关系。

## 2. 生活场景创意方向

**先写产品特定的故事，再选道具。** 故事从 `art_direction.buyer_reading` 里买家想象的那一幕来。一句话：`这个产品帮助 <买家> 在 <真实使用时刻> 中/后 体验或表达 <具体结果>`。然后按三拍推进：`desire`（买家立刻把产品放进对的世界）→ `use`（可信的动作证明产品如何参与）→ `ownership`（首次使用后产品仍有意义、有用、可陈列、可送、可记）。故事必须依赖这个产品的类目、设计、个性化、材质或功能；换成无关产品也成立的概念太泛。不虚构仪式、传承、收件人、包装、工艺或内含配件。

**场景世界，不是背景替换。** 按受支持的买家问题选场景世界；一个地点的不同空间关系或几个相关场景都可以，不强制场地数。每个世界要有：买家旅程中的目的、环境与光线条件、色板与明度结构、一个主要空间锚、一个不同的产品状态或互动、一个相机族与视距、不超过一个锚道具家族。用两三个手法保持统一（产品色、阴影柔度、材质、调色），用时刻和视觉结构的变化制造差异。每张生活图展示一个**不同的时刻**；类目和证据支持时至少包含一次真实功能互动和一次拥有/结果场景。

**视觉层次。** 阅读顺序：产品或产品动作 → 相关的手/穿戴者/使用结果 → 环境与道具。小产品在普通生活镜头里通常占画面 30%–60%，更宽的比例证明是明确例外；此范围不套用于家具、墙面艺术、服装合身或房间尺度产品。拒绝：道具、模特或建筑变成真正主体；缩略图下产品难辨认；浅色产品 + 浅色台面 + 平光融成低对比一片；浅景深糊掉买家关键细节。不因为"看起来干净"就默认整套浅中性色、平高调光或单一色系。

**道具即证据。** 每个道具至少做一件事：建立使用情境、证明比例、使动作成立、标识买家或场合、支持已验证的季节/风格、强化对比。删掉只填空的道具和默认填充簇（花 + 亚麻 + 咖啡 + 书及其类目等价物）。同一道具家族复用需要不同的时刻与构图。绝不让造型暗示未包含的物品、礼盒、支架、画框、工具或配件是购买的一部分。

**人物互动可信。** 先遵守 `human_presence_budget`。写清身体裁切、握法、用力方向、接触点、必须保持可见的产品细节。偏好自然的压力、重量、褶皱、运动或位移，手握在结构上合理的位置。拒绝：装饰性的模特式手；不可能的握法、比例、手指数、接触或工具角度；对周边材料没有物理影响的动作；声称使用中却完美未动的食物、织物、表面；遮挡产品或把图变成泛用库存图的人物。

**为时刻写 prompt，不为形容词写。** 用可观察的决定替换 `luxury`、`beautiful`、`cozy`、`Pinterest style`：具体环境与买家时刻、产品位置与动作、背景相对产品的明度、主次色、表面材质、相机高度/角度/距离/焦点、光源方向/柔度/阴影/反射、该镜头 `mood_profile` 对应的色彩要求、一两个真实感线索、要排除的默认填充、这张与其他图必须不同的地方。每个生活 prompt 加一行 shot 专属的 `anti_template`，点名这张图必须避开的重复处理，不用通用负面清单。

## 3. 色彩准确、氛围与白平衡门

两件事分开管：**产品的颜色永远要准**；**画面的气氛跟着美术方向走**。一律压成中性日光，会把圣诞、秋冬、烛光餐桌这类本该有温度的时刻拍成目录图；放任模型自己加暖，又会整帧泡黄，白变象牙、银变金。所以先选档，再按档写、按档测。

### 3.1 选 `mood_profile`

写在 `art_direction` 里，整套一个档。

| 档 | 什么时候用 | 画面 |
| --- | --- | --- |
| `true_color`（默认） | 没有充分理由用暖调的一切：银、白金、玻璃、白色和浅色产品，需要精确辨色的品类，明亮通透的婚礼、婴童、春夏场景，所有 proof_led 产品 | 中性、色彩准确的日光（视觉上约 5000–5500 K），白和中性灰渲染为中性，不是奶油、黄、琥珀或橙 |
| `warm_scene` | 买家想象的那一幕本身是暖的：圣诞与冬季节日、烛光餐桌、秋季、壁炉边 | 画面有温度，但暖来自场景里说得出名字的光源和材质；打在产品上的光仍然中性，白仍然是白 |

- `art_direction.atmosphere.type` 是 `occasion_led` 且场合本身是暖的（圣诞与冬季节日、秋季、烛光餐桌、壁炉边）时，主图和场景图默认 `warm_scene`，不用另找依据；这类产品整套用 `true_color` 才要写理由。把暖全删掉换来的「色准」，是一套没人想买的目录图。
- 其他情况选 `warm_scene` 要在 `art_direction` 里有依据：场合、季节、买家那一幕。「好看」「有生活气息」不是依据。产品本身是金色、木质、皮质也不是依据：产品暖，环境更要干净，否则金对金、木对木，整帧糊成一片。
- **证据镜头永远 `true_color`**：颜色或材质比较、清单、细节微距、尺寸底图。`warm_scene` 的整套里，只有主图和生活、使用、拥有、送礼镜头可以暖，每张在计划里标 `mood_profile`。
- 这些是视觉目标，不是声称生成图的元数据里有测量的 Kelvin 值。

### 3.2 「太暖」的三个原因

买家说的「太暖」由三个独立原因叠加而成，分开诊断、分开处理：

| 原因 | 表现 | 测量信号 | `true_color` 镜头 | `warm_scene` 镜头 |
| --- | --- | --- | --- | --- |
| A. 白平衡偏黄 | 本该白或灰的物体发黄发橙，银和玻璃像金，肤色偏橙 | `neutral_b`（中性区 b*） | 失败。重写 `Color` 一句的正向锚点；小幅可确定性修正 | 同样是失败，只是阈值宽一档。加强打在产品上的中性补光后重生成，不做修正 |
| B. 暖色板垄断 | 白平衡是中性的，但整帧全是木头、亚麻、米色、奶油、金、黄铜，没有一块真正中性或偏冷的东西 | `frame_rb`（整帧 R/B）、`no_neutral_anchor` | 失败。换台面和背景材质，加中性锚点；**白平衡修正救不了** | 暖色板是方向的一部分，`frame_rb` 只记录；但画面里必须留一块真正的白，`no_neutral_anchor` 仍是失败 |
| C. 暖光源 | 蜡烛、灯串、钨丝台灯、夕阳窗光、壁炉以「道具」身份混进场景，实际是光源 | 肉眼加 A 的数值 | 例外，要登记，整套最多 2 张 | 允许，但只放在背景或侧后方，不当主光照产品 |

生图模型的默认审美会同时触发 A、B、C；必带的用户指令里「生活气息」一词会加重这个倾向，金色、木质、婚礼、节日、母婴类产品尤甚。默认假定模型会往暖拉。`true_color` 要主动往回拽；`warm_scene` 要把暖限制在该在的地方。

### 3.3 `true_color` 镜头怎么写

- prompt 收尾的 `Color` 一句**用正向可见锚点**写：点名画面里最大的那块白或灰物体，要求它渲染成纸白或中性灰；点名日光类型（阴天、北窗、开放阴影、柔光箱）；点名一个大面积中性或偏冷的锚点（白墙、灰石、黑色、银、玻璃、绿植、蓝）。不用 `no yellow / no amber / no warm` 这类否定清单，它们对生图模型基本无效，还会把这些词喂进去。
- **每张场景图至少一个大面积中性锚点**（估计 ≥ 15% 画面）；暖色材质（木、亚麻、米、奶油、金、黄铜、陶土、皮革）合计不超过约三分之一画面。在 `scene_anchor` 里注明锚点是什么。
- **表面色板与照明分开。** 米色、奶油、胡桃木、黄铜、秋季道具或情感亲密的场景，都不构成给产品或整帧加暖色调的理由。
- **蜡烛、灯串、钨丝台灯、壁炉、夕阳窗光是光源不是道具。** 用了就登记为 `color_temperature_exceptions` 和该 shot 的 `warm_light_source`（光源、局部范围、保持中性的区域）；整套最多 2 张，证据镜头不享有例外。保持**可见动机且局部**：保留中性白、准确产品色、自然肤色、中性补光，不让高光、中间调、阴影全泡在橙色里。
- 输出过暖时的修正顺序：先判断是 A、B、C 哪一种；A → 重述 `Color` 一句的正向锚点并点名发黄的那个物体；B → 换掉暖色台面和背景、加中性锚点、删暖道具；C → 删光源道具或登记例外。**不要只加 `cooler`**，那会把失败换成蓝青调。

### 3.4 `warm_scene` 镜头怎么写

- **暖从哪来要点名。** 写光源和它在画面里的位置：背景里虚掉的树灯，侧后方的一支蜡烛，从左侧低角度进来的傍晚窗光。说不出来源的暖就是色偏。
- **产品上的光是中性的。** 在 `Color` 一句里写明：产品由一侧的柔和日光或白墙反光照亮，颜色与参考图一致。暖光源不压在产品上。
- **留一块说得出名字的白。** 袜口的白毛、白漆壁炉台、白瓷杯、白墙。它应该是柔和的白，不是象牙黄。
- **不是越暖越好。** 高光不发橙，阴影不发棕，绿是绿，白是白。看起来像一张白平衡正确的照片拍到了一个暖的房间，而不是一张加了暖色滤镜的照片。
- 输出发黄时：先把暖光源挪远、挪到背景，再加强产品一侧的中性补光，点名那块发黄的白；不要整句改成冷调。

两档都一样：用可观察的环境、光源、方向、柔度、对比、阴影写画面，不用 `warm`、`cozy lighting`、`golden glow`、`sun-kissed`、`amber` 这类速记，它们会把整帧泡黄。

### 3.5 测量门（不凭肉眼）

肉眼看一整批暖图会色适应，看不出来。色偏用数值判定。每批生成后运行随 Skill 附带的脚本，`warm_scene` 镜头用 `--warm-shots` 列出编号：

```text
python scripts/color_cast_check.py <out-dir> --json <out-dir>/color-cast-report.json
python scripts/color_cast_check.py <out-dir> --warm-shots 1,7,9,15 --json <out-dir>/color-cast-report.json
```

| 指标 | `true_color` | `warm_scene` |
| --- | --- | --- |
| `neutral_b`（中性区 b*） | pass ≤ 3；borderline 3–6；reject > 6 | pass ≤ 8；borderline 8–11；reject > 11 |
| `frame_rb`（环境 R/B：整帧去掉橙黄色带以外的高饱和像素，红、绿、蓝色产品占满画面不算暖色板） | > 1.25 → `palette_warm_dominant`，按 B 处理 | 只记录，不判定 |
| `neutral_pct`（中性采样占比） | < 8% → `no_neutral_anchor`，按 B 处理 | < 4% → `no_neutral_anchor`：画面里的白全被染色了，按 A 处理 |
| 整套 `median_neutral_b`（只算 `true_color` 镜头） | ≤ 3；> 3 说明基线整体偏暖，检查共用的 prompt 措辞 | 不适用 |

- `reject` 一律重生成。
- `true_color` 的 `borderline` 二选一：重生成，或用 `--fix` 做确定性中性锚点白平衡修正（线性 sRGB 的 von Kries 增益，所需增益超过 ±20% 时脚本拒绝修正）。修正后的文件必须重新对照参考图核产品色，并在 `fidelity-audit.json` 记 `wb_corrected: true` 与增益；修正只解决 A，修正后仍 `borderline` 或带 `palette_warm_dominant` 的图按 B 重生成。
- `warm_scene` 的 `borderline` 只能重生成。脚本不修正暖镜头：把它拉回中性等于删掉了设计好的光。
- 未经用户明确批准，任何 `borderline` 图不进最终集。
- **`warm_scene` 的数值通过之后还有一道人工核对**：把产品从图里和参考图并排看，颜色必须一致。数值只量白，量不到产品。
- 审实际图不审 prompt。名义上白或中性的区域明显发黄发橙、肤色不自然地橙、银或透明材质看起来像金、产品偏离参考色、或某张 `true_color` 图明显比整套基线更暖且无记录例外 → 即便数值勉强通过也拒绝。数值是下限，不是免检。

## 4. 生活图创意评分（仅生活/拥有/使用场景）

五项各 0–2 分：`narrative_specificity`（这个场景只可能属于这个产品或买家时刻？）/ `product_prominence`（产品是清楚的主体且缩略图可辨？）/ `visual_distinction`（与其他生活图有实质差异且仍统一？写出最近的比较图与实质差异或合理复用）/ `interaction_authenticity`（使用、接触、运动、比例、物理响应可信？静态陈列评接触与放置，不要求虚构动作）/ `price_and_brand_fit`（色板、材质、光线、造型、克制支持目标定位？）。

通过线：≥ 8/10 且无 0 分项。五项都要写短的可见证据，不只写总分或场景名。这些分数不替代技术、状态、比较、数字图的决策特定证据检查；产品真实、漏掉的买家关键要求、整套多样性是独立的门，高分不能覆盖。含可见人体的图另记 `human_scale_status`（pass / borderline / reject），是硬门不是平均分：第一眼像迷你/玩具、手/身体压过产品、透视不一致 → reject；用户的比例否决覆盖内部通过。
