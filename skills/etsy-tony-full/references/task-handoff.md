# 同一任务中的交接

仅在当前交付需要跨能力，或长任务需要恢复进度时使用。单条标题、翻译或客户回复不创建交接文件。

## 传递哪些信息

用已有文件或简短内部记录传递：

- 当前对象：商品、SKU、文件或已明确的目标店铺/草稿 ID。
- 本轮结果：要交什么，以及什么证据能够判定完成。
- 已确认事实：区分用户确认、可观察外观、来源陈述、带日期的数据；保留来源和冲突。
- 未知与限制：原始 `Unknown` 等值、不可推导的字段、尚需样品或当前官方依据的结论。
- 已完成阶段：文件位置、实际读取的结果及其验收状态；不把上一能力的一句“完成”当作证据。
- 已有授权：本次允许的对象、范围和动作；用户批准概念不代表批准生产或发布。
- 当前主责：最终交付由哪个 Skill 汇总，下一步为什么是必要依赖。

字段只在有用时记录，不为凑表创建空值。一个任务可包含多张图或多份配套文件；“一个交付”指一个完整业务结果，不限制文件数量。

## 依赖怎样安排

先做会淘汰不可行方向或阻止错误成本的必要判断，再制作依赖它的产物；独立信息可并行读取。组合 Skill 不等于授权创建子代理、后台任务或外部模型调用，按当前环境与用户授权决定执行方式。

产品开发遵守制造、设计、原创性、SKU 与就绪的依赖。现有产品拍照则先建立产品事实和使用权限，再制作并审图；不强迫它重跑新产品开发。复用有效证据，只有对象、版本、时效或用户条件变化才重做相关检查。

辅助结果只回传影响当前决定的事实、结论、限制和证据位置。主责统一措辞和状态，不把几份重复长报告拼在一起。

## 缺口与结束

- 缺失事实只阻塞依赖它的字段或动作，独立草稿继续。
- 工艺失败时不推荐该设计；没有样品时保留生产未知；竞品证据不足时不能声称竞品支持充分。
- 登录、验证码或工具故障先读取现状；按相应工作流进行一次有依据的恢复，不能循环点击或重复写入。
- 改用其他流程会改变用户指定数据源、引擎、最终目标或授权对象时，不能静默替换。
- 最终回读在用户指定的目标上进行。完成当前结果就结束；需要选款或精确缺失信息时，说明已经完成的部分和最小解锁条件。

`VERIFIED_SUCCESS` 表示当前请求的关键验收通过。它不把“概念图通过”升级成“实物可生产”，也不把“本地草稿通过”升级成“后台已保存”。
